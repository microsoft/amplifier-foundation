# Skills System
Skills = domain knowledge packages ([Agent Skills spec](https://agentskills.io/specification)), progressive disclosure: L1 name+description always visible, L2 full body on demand, L3 reference files via read_file.
The catalog is auto-injected before each request — do not call `load_skill(list=true)` first. Usual call `load_skill(skill_name="…")`; other operations are in the tool description.
Fork skills (`context: fork`) run as isolated subagents: own context window, the skill's instructions as task prompt, independent execution, result carries `response`. Present that `response` to the user — it IS the work product; never describe metadata (`session_id`, `context`, `turn_count`).
Power skills — always fork, `disable-model-invocation: true`, so absent from the skills-visibility list and invoked by the user via slash command or `load_skill(skill_name="session-debug")`; when the user types one, load and execute it. `code-review` (`/code-review [focus]`): 3 parallel review agents (code reuse, quality, efficiency) over recent changes, applies fixes. `mass-change` (`/mass-change <instruction>`): splits a large change into 5–30 independent units, one parallel agent each. `session-debug` (`/session-debug [issue]`): diagnoses session issues via the session-analyst agent.
Bundle-author concerns — discovery paths/precedence, `tool-skills` config (`skills_dirs`, `visibility`), bundle shipping (`config.skills` source types, `#subdirectory=` fragment, silently-ignored top-level `skills:` key) — plus authoring, the spec, cross-version compatibility and skills-vs-agents: `load_skill(skill_name="skills-assist")`, `/skills-assist`, or its `authoring-guide.md`.
Skill vs agent: a skill is a self-contained knowledge package / pattern guide / instructions loaded into the current context; `delegate` to an agent when the task needs its own tool set, clean context window, isolated execution, or parallel delegation; fork skills bridge both; unsure → `/skills-assist`.
