# Amplifier Modes
Modes = runtime behavior overlays; an active mode injects guidance and enforces tool policies.
`/mode <name>` activate (toggles if active) · `/modes` list · `/mode off` deactivate.
An active mode shows as `<system-reminder source="mode-<name>">`, categorizes tools per its config, displays `[mode]>` to the user.
Policies: `safe` normal · `warn` first call blocked, retry to proceed · `confirm` user approval required before execution · `block` disabled. Unlisted tools → `default_action` (default `block`). Blocked/warned calls return a policy result: for `warn` state your intent and call again if appropriate; for `confirm` wait for the user's decision from the approval system.
`mode` and `todo` are infrastructure tools: always callable, bypassing the cascade under any `default_action`/`tools.*`, so `mode(operation="set"|"clear"|"list"|"current")` and `todo` are never blocked. Authors must NOT list them in `tools.safe`; the bypass is `hooks-mode` config (`infrastructure_tools: ["mode", "todo"]`, default); `default_action: block` without them is not a trap. See `mode-schema-reference.md §3.4`.
Custom modes: `.md` in `.amplifier/modes/` (project) or `~/.amplifier/modes/` (user-global); YAML frontmatter `mode:` (name, description, tool policies) + markdown guidance. Authoring (schema, fields, shortcut rules, `contributes` blocks, naming): read `@modes:context/mode-schema-reference.md` or delegate to `mode-author`.
In a mode the user explicitly chose it: follow its guidance, respect tool policies, honor user intent; never ignore guidance or route around restrictions; adapt, and suggest `/mode off` if the user needs restricted capabilities.
Agent-initiated: `mode(operation="list"|"current"|"clear")`, `mode(operation="set", name="plan")`. Gate policy defaults to `warn`: first request blocked with a reminder, call again to confirm.
Capabilities are ephemeral — modes add/remove tools, agents, skills, context. Currently-listed capabilities are authoritative: check the tools schema, `delegate` agent catalog, skills-visibility list, active-mode reminder before invoking anything. A capability from an earlier turn that is no longer listed came from a deactivated mode — do NOT re-invoke it, it will fail. Holds with or without an active mode, and for any future contribution mechanism beyond `tools`/`agents`/`skills`/`context`: trust the current set, not history.
